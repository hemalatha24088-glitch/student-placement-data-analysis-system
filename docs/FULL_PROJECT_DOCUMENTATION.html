Executive Abstract

Higher education institutions historically track campus placement drives using disparate manual spreadsheets. These manual approaches suffer from severe limitations: multi-offer duplication, inaccurate placement rate computations, missing prerequisite tracking, and a total absence of predictive intelligence.

The Student Placement Data Analysis System is a full-stack, centralized web application built using Python 3.14, Flask, MySQL 8.0, Pandas, NumPy, Matplotlib, and Scikit-Learn. It establishes a normalized 3NF relational schema enforcing strict referential integrity across students, corporate recruiters, technical skills, and placement offers.

To justify a B.Tech CSE (AI/ML) specialization, the system implements an enterprise-grade 4-Pillar Artificial Intelligence and NLP Suite:

  • Supervised Classification: Random Forest Classifier predicting student placement probability and risk tier.
  • Recommender Systems: Recruiter Tier Profiling and 6-Week Structured Preparation Roadmaps.
  • Supervised Regression: Random Forest Regressor predicting expected annual CTC (in ₹ LPA) with dynamic confidence intervals.
  • Natural Language Processing (NLP): TF-IDF N-Gram Vectorizer and Cosine Similarity calculating real-time ATS compatibility scores against corporate Job Descriptions (JDs).

The system is verified with 36 automated unit tests (100% passing) and is deployed live via secure Cloudflare Zero-Trust tunnels.

Database Relational Entities (3NF Normalized)

The database schema placement_db is normalized to Third Normal Form to ensure zero data redundancy:

  • students: Primary master record (student_id, roll_no, student_name, department, graduation_year, cgpa, eligible_for_placement).
  • skills: Master skill catalog (skill_id, skill_name, skill_category).
  • student_skills: Associative bridge table resolving M:N relationship with composite primary key (student_id, skill_id).
  • companies: Corporate recruiting partners with hiring tier classifications (Super Dream, Dream, Core, Mass).
  • placements: Comprehensive placement offers (student_id, company_id, package_amount, role, status, placement_date).
  • users: System administrator and placement officer authentication credentials with hashed passwords.

Chapter 2: The 4-Pillar AI, Machine Learning & NLP Suite

Pillar 1: Placement Probability Predictor (Classification)

An ensemble Random Forest Classifier evaluates candidate parameters to output placement probability. Features include academic GPA, department one-hot encoding, total skill count, and key skill flags (DSA, Python, SQL, AI/ML, Cloud).

  • Model Accuracy: 85.0% | Precision: 88.9% | Recall: 80.0%
  • Top Feature Importance: Cumulative GPA (63.8%), followed by Data Structures & Algorithms (11.2%).

Pillar 2: Smart Skill Gap Recommender Engine

Benchmarks student skill inventories against campus recruitment tier standards (Super Dream > 15 LPA, Dream 8-15 LPA, Core 6-12 LPA, Mass 3.5-7 LPA). Calculates weighted competency affinity and generates an actionable 3-phase, 6-week preparation roadmap.

Pillar 3: Salary Package (CTC) Predictor (Regression)

A supervised Random Forest Regressor trained on 47 verified placement compensation packages in MySQL. Predicts annual CTC point estimates and dynamic confidence intervals.

  • Mean Absolute Error (MAE): ±₹3.63 LPA | RMSE: ₹5.04 LPA
  • Sensitivity Analysis: Quantifies the monetary CTC uplift for each unpossessed skill and estimated gain per +0.50 CGPA.
  • Verified Bio-Data Generator: Official printable candidate placement resume with TPO seal.

Pillar 4: AI Resume & Job Description Matcher (NLP)

Applies TF-IDF N-Gram Vectorization (unigrams & bigrams) and Cosine Similarity to measure semantic alignment between student resumes and recruiter Job Descriptions (Google SWE, Amazon SDE-1, Microsoft Cloud & AI, TCS Digital, Deloitte). Extracts matched competencies and isolates missing recruiter keywords to calculate ATS Pass Scores.

Essential Faculty Review Questions

Q: Why did you use PyMySQL with parameterized queries instead of an ORM like SQLAlchemy?
A: Parameterized SQL queries ensure full transparency and complete defense against SQL injection. In an academic project review, writing explicit SQL queries and using DictCursor allows faculty to evaluate our mastery of relational database design and indexing rather than relying on abstract ORM layers.

Q: How do you prevent thread collision with Matplotlib in Flask?
A: We enforce matplotlib.use("Agg") prior to importing pyplot. The 'Agg' backend renders charts strictly in memory to raw byte streams without requiring desktop GUI window managers, preventing server crashes during concurrent multi-threaded requests.

Q: How does your system assist institutions during NAAC or NIRF audits?
A: NIRF and NAAC require exact, auditable placement statistics, median CTC packages, and verified proof of career counseling interventions. Our system calculates true distinct placement rates, exports accredited CSV reports, and logs candidate skill gap remediation.
